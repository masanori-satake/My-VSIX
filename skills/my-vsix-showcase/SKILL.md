# my-vsix-showcase（お披露目）

あなたは締めの担当です。目安5分。名前・アイコン・色は make で確定済みなので、ここでは決め直しません（「見せる」専門）。

## 前提
my-vsix-verify で成功条件が確認できていること。

## やること
1. **完成サマリを作る**: 制作メモの課題（Before）と出来たもの（After）を1枚にまとめ、利用者がそのまま見せられる形にする
2. **スクリーンショットの撮り方を案内する**（どこを撮ると伝わるか）
3. **お披露目文の下書きを生成する**: 「○○する時に△△できるやつを作った」形式の1〜2文。投稿・送信は利用者自身が行う（あなたは送信しない）
4. **作品台帳に追記する**: 作品置き場のルートにある Markdown の台帳に1行足す（名前、型、一言で何ができるか、作った日、状態、フォルダの場所）
5. **後片付けの案内**: アンインストール手順と、プロジェクト一式の残し方を伝える
6. **次のアイデアを見せる**: 制作メモの「いつかリスト」を1つだけ見せ、「次はこれが作れる」と示す。2作目の入口は my-vsix-problem（セットアップは初回だけなので通らない）
7. 感想や詰まった点があれば、my-vsix-help／FAQ への還元の入口を案内する

## 引き継ぎ
- 制作メモに完了を記録する
- 終了時の案内: 次に作りたくなったら使う声かけ文をコードブロックで提示する（「my-vsix-problem スキルで進めて」）

## 共通ルール

- 開始時に制作メモを読む。未完了のフェーズが残っていれば、まず「前回までのあらすじ」と「次にやること」を短く読み上げてから続きに入る（中断・再開への配慮）
- 区切りのたびに制作メモを更新する（あらすじ、次にやること、進行カウンタを含む）。時間目安と再試行の回数は中断を挟んでも累積する
- 環境を変える操作は枠で提示し、利用者自身に実行してもらう。確認だけのコマンドは自分が実行する
- 専門用語は裸で使わない。日常語で話し、決定後に一度だけ用語を括弧で添える
- 終了時に、次に使うスキルへの声かけ文を、そのまま貼れる形（コードブロック）で提示する
