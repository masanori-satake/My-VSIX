# 事前準備ガイド

<p align="center"><a href="../assets/birds.md"><img src="../assets/illustrations/bird-setup-suzume.webp" width="320" alt="スズメ（準備）" title="スズメ（準備の案内役）"></a></p>

体験会や自習の **当日ではなく、事前に** 終わらせておくためのガイドです。
このガイドで必須なのは、道具のインストールまでです。フックの初回実行（ダウンロードを含む）は、当日にセットアップのスキル（my-vsix-setup）が案内して行うので、ここでは行いません。回線が遅い環境の方のために、任意の先行実行だけステップ3に残してあります。

## 用意するもの（システム側はこの3つだけ）

1. Python（保証範囲は 3.11〜3.14 です）
2. pre-commit（指定版は 4.7.0 です）
3. git（キットのコピーと、ビルドの仕組みの前提です）

版数の根拠は [バージョン固定表](version-pins.md) にあります。

Node.js は **不要** です。ビルドに必要なプログラム（Node.js や、VSIX を作るための vsce）は、pre-commit が管理する仮想環境の中に自動で用意されます。

## コマンドを打つ場所

このガイドのコマンドは、**キットのフォルダを開いた VS Code（または Kiro）の内蔵ターミナル**で打つのが確実です。内蔵ターミナルは、メニューの「ターミナル」→「新しいターミナル」で開きます。

## 手順（1ステップずつ）

### ステップ0: git の確認とキットのコピー

```
git --version
```

バージョンが表示されればOKです。キットのコピーは **git clone** で行ってください。GitHub の画面から ZIP でダウンロードしたものは、ビルドの仕組み（pre-commit）が動きません（`FatalError: git failed` と表示されます）。

### ステップ1: Python の確認

```
python --version
```

保証範囲（3.11〜3.14）のバージョンが表示されればOKです。表示されない・範囲外の場合は、Python の公式サイトから保証範囲内の版を入れ直してください。

つまずきやすいのは次の3つです。

- **Microsoft Store の画面が開いた** → Python がまだ入っていない合図です。Store からではなく、Python の公式サイトから入れてください
- **入れたのに「表示されない」** → インストールの途中で「Add python.exe to PATH」にチェックを入れ忘れていることが多いです。入れ直すときに確認してください
- **`python` で何も起きない** → `py --version` でも確認できます。こちらで保証範囲内が表示されれば大丈夫です

### ステップ2: pre-commit の確認

```
pre-commit --version
```

指定版（4.7.0）が表示されればOKです。

### ステップ3（任意）: フックの初回実行を先に済ませる

このステップは **任意** です。飛ばしても構いません。

フックの初回実行では、初回だけ必要なダウンロード（Node.js や vsce など）が起きます。これは当日にセットアップのスキル（my-vsix-setup）が案内して行うので、通常はここで実行する必要はありません。回線が遅い環境で当日に待ちたくない方だけ、先に済ませておくと当日のセットアップが短くなります。

キットのフォルダで、次を実行してください。

```
pre-commit run --all-files --hook-stage manual --verbose
```

実行すると、テンプレート3型（command／display／showcase）のチェックが順に走ります。裏側では、型ごとに単独のフォルダとしてビルドまで試しています。チェック自体はキットに用意してある「事前準備チェック」が自動で行うので、フォルダを移ったりコピーしたりする必要はありません。

（`--verbose` は、チェックの途中経過を表示するための指定です）

所要時間の目安: 初回の実行は、作者の環境では **約1分** でした。ネットワークが遅い環境では数分〜十数分かかることがあります。止まっているように見えても、初回はダウンロードの途中なので、そのまま待ってください。

実行した場合のうまくいった状態は、型ごとに次の2行が表示され（3型分で合計6行）、最後に「事前準備チェック: すべて Passed です。初回ダウンロードも終わりました。」と表示されることです。

```
機械ガード（約束チェック）...............................................Passed
構文チェックと VSIX 化...................................................Passed
```

`Failed` と表示された場合は、うまくいっていません。その画面の表示をそのまま AI に見せてください（直し方を案内します）。

## 動作確認基準（全部に当てはまれば準備完了）

- [ ] `git --version` でバージョンが表示され、キットは git clone でコピーした
- [ ] `python --version` で保証範囲内（3.11〜3.14）のバージョンが表示される
- [ ] `pre-commit --version` でバージョンが表示される
- [ ] 使っているエディタ（VS Code／Kiro）のバージョンが下限（土台 1.100）以上である（確認方法: エディタの「バージョン情報」の画面。根拠は [バージョン固定表](version-pins.md)）
- [ ] （任意）キットのフォルダで `pre-commit run --all-files --hook-stage manual --verbose` を実行し、事前準備チェックがすべて Passed になる（初回ダウンロードを先に終わらせたい場合のみ。当日は my-vsix-setup が案内します）
- [ ] AI ツール（Copilot／Kiro）で my-vsix-setup スキルが認識されている

## キットをやめるとき

仮想環境（ダウンロードした Node.js や vsce など）は、pre-commit のキャッシュの中にあります。次を実行するとまとめて消えます。

```
pre-commit clean
```

あわせて、作品ごとに作ったフォルダと、エディタ側の拡張を削除すれば元通りです。
