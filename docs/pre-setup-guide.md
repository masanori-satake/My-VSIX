# 事前準備ガイド

体験会や自習の **当日ではなく、事前に** 終わらせておくためのガイドです。
当日は「作る」ことに集中できるよう、時間のかかるダウンロードは事前に済ませておきましょう。

## 用意するもの（システム側はこの2つだけ）

1. Python（保証範囲は 3.11〜3.14 です）
2. pre-commit（指定版は 4.7.0 です）

版数の根拠は [バージョン固定表](version-pins.md) にあります。

Node.js は **不要** です。ビルドに必要なプログラム（Node.js や、VSIX を作るための vsce）は、pre-commit が管理する仮想環境の中に自動で用意されます。

## 手順（1ステップずつ）

### ステップ1: Python の確認

```
python --version
```

保証範囲（3.11〜3.14）のバージョンが表示されればOKです。表示されない・範囲外の場合は、Python の公式サイトから保証範囲内の版を入れ直してください。

### ステップ2: pre-commit の確認

```
pre-commit --version
```

指定版（4.7.0）が表示されればOKです。

### ステップ3: フックの初回実行

テンプレートのフォルダ3つすべてで、順に次を実行してください（`templates/command/`、`templates/display/`、`templates/showcase/`）。あとでどの型を選んでも、当日にダウンロードで待たずに済むようにするためです。ここでの目的は作品を作ることではなく、初回だけ必要なダウンロード（Node.js や vsce など）を終わらせておくことです。2つ目以降は使い回しが効くので、短時間で終わります。

```
pre-commit run --all-files
```

（フックの導入 `pre-commit install -f` は、自分の作品プロジェクトを作る時に setup スキルが案内します）

### うまくいった状態

3つのフォルダすべてで、実行の最後に次のように表示されれば成功です（フォルダごとに2行ずつ出ます）。

```
機械ガード（約束チェック）...............................................Passed
構文チェックと VSIX 化...................................................Passed
```

あわせて、各フォルダの中に `dist` フォルダができ、その中に `.vsix` で終わるファイルが入っています。

`Failed` と表示された場合は、うまくいっていません。その画面の表示をそのまま AI に見せてください（直し方を案内します）。

## 動作確認基準（全部に当てはまれば準備完了）

- [] `python --version` で保証範囲内（3.11〜3.14）のバージョンが表示される
- [] `pre-commit --version` でバージョンが表示される
- [] `pre-commit run --all-files` で2つとも Passed になる（テンプレート3フォルダすべて。初回ダウンロードが終わっている）
- [] AI ツール（Copilot／Kiro）で my-vsix-setup スキルが認識されている

## キットをやめるとき

仮想環境（ダウンロードした Node.js や vsce など）は、pre-commit のキャッシュの中にあります。次を実行するとまとめて消えます。

```
pre-commit clean
```

あわせて、作品ごとに作ったフォルダと、エディタ側の拡張を削除すれば元通りです。
